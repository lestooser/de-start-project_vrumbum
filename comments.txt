Этот файл содержит описание проекта по нормализации данных о продажах автомобилей.

================================================================================

1. ОБЩЕЕ ОПИСАНИЕ ПРОЕКТА
================================================================================

Цель: нормализовать сырые данные (таблица raw_data.sales) в реляционную модель данных до 3-й нормальной формы,
устранить избыточность, выделить отдельные сущности (бренды, модели, цвета, покупатели)
и обеспечить ссылочную целостность. В результате создана схема car_shop с шестью таблицами.

Исходные данные:

- Таблица raw_data.sales содержит 1000 записей о продажах автомобилей.
- Поля: id, auto, gasoline_consumption, price, date, person, phone, discount, brand_origin.
- Поле auto имеет формат: "Бренд Модель, цвет".
- Для электромобилей gasoline_consumption = NULL.
- Для некоторых брендов brand_origin = NULL.

================================================================================

2. СТРУКТУРА НОРМАЛИЗОВАННОЙ СХЕМЫ (car_shop)
================================================================================

2.1. Таблица brands

- Назначение: справочник брендов.
- Поля:

- brand_id (serial, PRIMARY KEY) – суррогатный идентификатор.
- name (text, NOT NULL, UNIQUE) – название бренда (извлекается из auto как первое слово).
- brand_origin (text) – страна происхождения (может быть NULL).

2.2. Таблица models

- Назначение: справочник моделей автомобилей (без цвета).
- Поля:

- model_id (serial, PRIMARY KEY).
- brand_id (int, REFERENCES brands) – внешний ключ на бренд.
- name (text, NOT NULL) – название модели (все слова после бренда до запятой).
- gasoline_consumption (numeric(3,1)) – расход топлива (NULL для электромобилей).
- Ограничения: UNIQUE (brand_id, name) – у одного бренда не может быть двух одинаковых моделей.

2.3. Таблица colors

- Назначение: справочник цветов.
- Поля:

- color_id (serial, PRIMARY KEY).
- name (text, NOT NULL, UNIQUE) – название цвета (извлекается после запятой).

2.4. Таблица model_with_colors

- Назначение: связь многие-ко-многим между моделями и цветами (одна модель может быть разных цветов, один цвет – у разных моделей).
- Поля:

- model_color_id (serial, PRIMARY KEY).
- model_id (int, REFERENCES models).
- color_id (int, REFERENCES colors).
- Ограничения: UNIQUE (model_id, color_id).

2.5. Таблица buyers

- Назначение: справочник покупателей.
- Поля:

- buyer_id (serial, PRIMARY KEY).
- name (text, NOT NULL) – ФИО покупателя.
- phone (text, NOT NULL) – телефон.
- Ограничения: UNIQUE (name, phone) – предполагаем, что комбинация ФИО+телефон уникальна.

2.6. Таблица sales (нормализованная)

- Назначение: факты продаж.
- Поля:

- id (serial, PRIMARY KEY).
- model_color_id (int, REFERENCES model_with_colors) – ссылка на конкретную модель с цветом.
- buyer_id (int, REFERENCES buyers) – ссылка на покупателя.
- price (numeric(9,2), NOT NULL) – цена со скидкой.
- discount (int2, DEFAULT 0) – скидка в процентах.
- purchase_date (date, DEFAULT current_date) – дата покупки.

================================================================================

3. ЭТАПЫ ЗАГРУЗКИ ДАННЫХ (ПОРЯДОК ВЫПОЛНЕНИЯ)
================================================================================

3.1. Создание и заполнение сырой таблицы

- Создаётся схема raw_data и таблица sales.
- Данные загружаются из CSV с помощью \copy (HEADER, NULL 'null').

3.2. Заполнение справочников

- brands: извлекаются уникальные бренды (первое слово из auto) и соответствующие brand_origin.
- models: извлекаются уникальные пары (бренд, модель) с расходом топлива. Название модели – всё, что идёт после бренда до запятой, с удалением лишних пробелов.
- colors: уникальные цвета (после запятой).
- model_with_colors: все сочетания model_id и color_id, встречающиеся в данных.

3.3. Заполнение таблицы покупателей

- Уникальные пары (person, phone).

3.4. Заполнение нормализованной таблицы продаж

- Для каждой записи raw_data.sales находятся соответствующие model_color_id и buyer_id, затем вставляются цена, скидка, дата.

================================================================================


ПРОВЕРКА ЦЕЛОСТНОСТИ ДАННЫХ
================================================================================

После загрузки выполнены проверки:

- Количество записей в raw_data.sales и car_shop.sales совпадает (1000).
- Сумма цен совпадает.
- Все внешние ключи корректны (нет "висячих" ссылок).
- Все уникальные ограничения соблюдены (нет дубликатов).
